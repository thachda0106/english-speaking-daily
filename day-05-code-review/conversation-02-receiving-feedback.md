# Day 5 · Conversation 2 — Receiving the Feedback

## 🎬 Situation
The review came back. Good news: it's mostly positive. There are a few small problems. Receiving feedback well = listening, asking for specifics, promising the fix.

## 🗣️ Dialogue — read out loud (both roles), then play the audio and answer

> **Colleague:** Okay, I looked at your pull request. It looks good overall.

> **You:** Great, thank you for the review. Did you find any problems?

> **Colleague:** A few small things. The variable names in the new function are a bit confusing.

> **You:** I see, that's fair. Which ones do you mean?

> **Colleague:** Let me point them out on the pull request. I also think we can do the loop one time less.

> **You:** Got it. I'll fix the names and check the loop logic again.

> **Colleague:** Perfect. Let me know when it's ready, and I'll approve it.

## 🧠 Your active vocabulary — all words you already know
`looked · pull request · good overall · review · problems · small · variable · names · function · confusing · fair · point · loop · fix · names · logic · ready · approve`

## ✅ After you speak
- The receiving-feedback formula = **thank + ask for specifics + promise the fix**:
  *"Thank you for the review. Which ones do you mean? I'll fix them and check the logic again."*
- 💡 **"That's fair."** = "I accept your point." The #1 phrase of the code review — say it warmly, not defensively.
- 💡 **"Which ones do you mean?"** — asking for specifics is a skill. It shows you want to improve, not argue.
- 🎙️ Play `colleague-02` and answer. Now say your reaction to a REAL review comment you received — using "That's fair."
