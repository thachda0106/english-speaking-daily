# Day 3 · Conversation 4 — Asking for Help

## 🎬 Situation
Your second day. You're reading the code and you're stuck on something small. Asking for help the RIGHT way is a skill — the team judges how you ask, not that you ask.

## 🗣️ Dialogue — read out loud (both roles), then play the audio and answer

> **Colleague:** How's it going with the code?

> **You:** Pretty well, thanks. I understand the main flow now, but I have a few questions.

> **Colleague:** Sure, ask away.

> **You:** First — how do you run the project locally? I saw the document, but I'm missing one step.

> **Colleague:** Ah, you need to set the database URL in the config file. I'll show you after the meeting.

> **You:** That would be great. And who should I ask about the deployment process?

> **Colleague:** Talk to the tech lead for that. He knows the production setup best.

> **You:** Perfect, I'll do that. Thanks for your help.

> **Colleague:** No problem at all. We're all happy to help new people.

## 🧠 Your active vocabulary — all words you already know
`code · understand · main · flow · questions · run · project · locally · document · missing · step · database · URL · config · file · meeting · deployment · process · tech lead · production · setup · help · problem · happy`

## ✅ After you speak
- The perfect "ask for help" formula — **say what you tried + name the exact gap**:
  *"I saw the document, but I'm missing one step."* — This is the KEY phrase. It shows you tried first.
- 💡 **"I'm missing one step."** / **"I'm stuck on X."** — both tell the team exactly where you are. Never just say *"It doesn't work"* — always say what you tried.
- 💡 **"ask away"** means "go ahead, ask!" — informal and friendly.
- 🎙️ Play `team-04`. Then ask a REAL question about the project using the formula: *"I tried X, but I'm missing Y."*
